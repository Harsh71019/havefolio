# PER-48: structured logging and optional Seq delivery

API and worker use the server-only `@havefolio/logging` package with NestJS Pino. Production emits JSON to stdout, preserving Docker's existing three rotating 10 MiB log files per container. Local development can select `LOG_PRETTY=true`; both destinations receive the same sanitized field meanings. Framework strings become bounded `framework` events rather than free-form messages. Authentication and media recovery emit structured events without identities or content.

## Schema and context

Every configured event includes `application`, `service`, `environment`, `release`, numeric Pino `level` and millisecond epoch `time`. Business events carry allowlisted `event`, `component`, `operation`, `category`, `code` and bounded numerical counts. HTTP completion adds `method`, registered `route` template (or `/unmatched`), `status`, `durationMs`, `requestId` and `correlationId`. Successful health traffic is debug-only. Controlled 4xx events are warnings, deliberate 5xx service failures are operational failures, and unexpected 5xx failures are errors. Finish/close share a guard so one completion is emitted, including aborted responses as 499. Automatic Pino HTTP access logs are disabled.

Request IDs accept only 16–64 ASCII letters/digits/underscore/hyphen; invalid, duplicate/array or missing IDs receive `crypto.randomUUID()`. The API returns `X-Request-ID`. `X-Correlation-ID` has identical validation, defaulting to the effective request ID. Neither header grants authorization. Do not put private values in correlation identifiers. AsyncLocalStorage carries a frozen per-request context through awaited services, without mutable global request fields. The exception filter stores failures only on the local response for completion classification.

Queue producers call `correlatedJobData(payload)` before `queue.add()`; this copies payload data and adds bounded metadata from the current context. There is currently no application API queue producer; the system worker consumes this contract and tests exercise a producer and retries. Metadata retains the logical correlation ID, originating request ID and immediate causation ID. The worker recomputes the current job ID/attempt rather than trusting them in the payload. Legacy jobs lacking valid metadata use a deterministic SHA-256-derived correlation identifier based on job ID across retries. The system processor emits `job_started`, `job_completed`, `job_retry`, `job_failed` and `worker_error`; unsupported operations use a fixed operation/error code, never the supplied job name. Payloads are excluded.

## Privacy boundary

Logging has an allowlist at the Pino call hook and a second boundary before either sink, including child logger bindings. It excludes bodies, DTOs, headers, query strings, raw URLs, arbitrary messages, provider responses, SQL parameters and arbitrary nested objects. Recursive defensive redaction copies inputs, removes secret/content keys regardless of casing, skips getters, limits recursion to five levels, arrays to 16 entries, objects to 32 properties and strings to 256 characters. It removes control characters and paths/URLs. Error messages are deliberately omitted: retain known error type, restricted operational/SQLSTATE code and at most eight sanitized frame line/column pairs, with no function names or local paths. No original filenames, multipart data, images, receipt/warranty contents, notes, cookies, sessions, passwords, keys or signed URLs belong in log fields.

The shared and HTTP/worker tests seed synthetic canary values at runtime and inspect both console and CLEF output. Bootstrap failures use a fixed JSON event without serializing configuration/dependency exceptions.

## Configuration and delivery

Server-only settings are `LOG_LEVEL`, `LOG_APPLICATION`, `LOG_SERVICE` (defaults to process api/worker), `NODE_ENV`, `LOG_RELEASE`, `LOG_PRETTY`, `SEQ_ENABLED`, `SEQ_ENDPOINT`, `SEQ_API_KEY`. Application/service/release fields are bounded tokens. Booleans accept only true/false. Invalid or placeholder Seq credentials and unsafe endpoints disable ingestion and retain console logging. A valid endpoint is an internal HTTP/HTTPS base URL or `/ingest/clef`, without URL credentials, queries or fragments. Compose supplies service and immutable release metadata and forces production JSON. Do not expose any telemetry settings through `NEXT_PUBLIC_` variables.

Delivery uses Seq's [HTTP CLEF ingestion API](https://docs.datalust.co/docs/posting-raw-events), posting newline-delimited events with `X-Seq-ApiKey` and `application/vnd.serilog.clef`. Console receives the sanitized JSON first. Seq uses a maximum of 256 pending events, a 1 MiB byte ceiling, 16 events/64 KiB per batch, at most 4 KiB per event and one in-flight batch. Each attempt times out after one second; two attempts maximum, then drop. Permanent 4xx responses are not retried; transient failures/429 receive one retry. Next batches wait one second, avoiding an outage retry storm. Timers are unreferenced and shutdown aborts in-flight requests and discards pending telemetry. No request/job awaits Seq. Recent Seq events can be lost on overload/outage/shutdown; console remains the fallback. Seq is absent from dependency startup checks, liveness and readiness.

## Protected deployment and verification

Use the existing internal Seq service and a dedicated Havefolio ingest-only key. Do not grant application credentials query/admin permission. Put `SEQ_ENABLED`, internal `SEQ_ENDPOINT` and the key only in existing root-protected API/worker deployment env files; keep placeholders in committed examples. The current Seq container is on its existing bridge network; select a reachable private ingestion endpoint from the Havefolio network without adding a public binding, second container or restarting shared services. Keep the previous Compose/release selector for rollback. No migration, media model change, external analytics or new data service is required.

On CT102, inspect disk/memory and build/load immutable API and worker images before a candidate run. Use controlled synthetic HTTP success, validation failure and server failure plus system job success/retry/terminal failure events; mark the release and operation as verification. Query Seq with an operator identity by request ID, release and service, and search for every seeded canary. Verify `docker logs` retains JSON. Test outage using an unreachable candidate-only endpoint; never stop Seq or modify shared-service networking. Record counts and IDs rather than raw private output. Remove candidate containers and their test resources; clearly identify verification events if retained. Recreate only Havefolio API/worker after a verified rollout, retaining PostgreSQL/Valkey and unrelated services.

Full retention, sampling, alerting and Beszel belong to PER-51; GlitchTip is PER-49 and health/Gatus is PER-50. This ticket does not add product analytics or log private inventory content.
